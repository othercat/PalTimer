# PalTimer 3.37.7 比赛联机与排名

显示版本 3.37.7，文件及程序集版本 3.37.7.4。旧核心继续使用 PalServer PR #11 的 `PAL98.TimerCompetition.v1`；默认自动玩法核心使用 `PAL98.TimerCompetition.v2`，须部署配套玩法规则及吴强硬核榜服务端。仅部署旧 v1 服务不能完成 v2 上传及硬核榜验收；本地计时和自动分类不依赖服务器。

自动核心新增综合／硬核节点参考选择及硬核前三（保留并列）；服务器只接纳主办方登记的玩法，不把所有本地自动分类都纳入比赛。服务端不支持 v2 时保留本地待传记录，不删除玩法字段降级上传；查询未取得有效结果时显示“未知”。详见 [自动玩法时间线实验](GAMEPLAY_TIMELINES_EXPERIMENT.md)。

## 使用

1. 主办方在配套游戏配置工具的“服务器上传配置 → 小柔服务器”设置开关、地址、比赛编号、规则编号，保存后可随整份配置锁定和分发。默认关闭；字段默认值为 `https://www.pallab.top`、`wuqiang`、`wuqiang-2026-v1`。
2. 计时器连接 PAL 后，在后台读取该 PAL 进程实际所在目录的配置。锁定包只采用通过签名校验的快照；旧配置没有此设置时保持关闭，不继承计时器原来的本机联机开关。计时器菜单“比赛联机与排名…”只显示有效联机信息，不提供服务器编辑入口。
3. 把页面中的设备标识交给主办方，在服务器后台绑定玩家名字。名字改动会由后台查询刷新，无需重新上传历史成绩。
4. 重置并开始一轮完整计时。每个已完成节点查询参考排名，通关先签封并保存本机记录，原生产构建及当前上传构建获批后才自动上传。中途开启、导入成绩或现有计时规则不允许的记录仅保存在本机。
5. 可开启独立比赛排名窗口，在 OBS 的“窗口捕获”选择“仙剑98自动计时器 - 比赛排名”。窗口保留固定捕获名称，但没有可见标题栏；不替换既有 DX9 遮罩。
6. 在计时器设置页选择透明背景、字体、8–72 号基准字号、文字颜色及居左／居中／居右。勾选“允许拖动及边缘缩放”后拖动正文可移动，拖动边缘可调整大小，文字按宽度同比缩放；录制时可取消该选项隐藏编辑边框。位置、尺寸和外观仅保存在本机，“重置遮罩位置”可找回移出屏幕的窗口。

只自动选择上传和排名赛道，不自动切换计时器内核或修改游戏。现有核心与游戏不匹配时的规则继续保留。

| 实际黑屏／走速 | 远程赛道 |
| --- | --- |
| 1200 ms／10（1.2秒＋普通） | `wuqiang` |
| 800 ms／10（0.8秒＋普通） | `wuqiang-800` |
| 800 ms／9（0.8秒＋快走） | `wuqiang-800-speed` |

实际模式取自原有已校验运行时快照，不读 INI 猜测；未知或第四种组合不自动上传。比赛开关由当前游戏配置决定；通关上传另须通过独立的构建激活与签封校验，不能用云 ID 或 HWID 绑定代替。详见 [独立上传激活](COMPETITION_UPLOAD_AUTH.md)。原录像审核／奖金榜独立不变。

## 排名含义

- 完整最佳线：取每位玩家最快完整通关线，在当前节点的累计时间比较。
- 单节点最佳：取每位玩家所有有效完整记录在这个节点的最快累计时间比较。
- 历史总榜：本人的历史最佳通关总时间；途中累计时间不参与完整通关排名。
- 本次通关：本轮成功上传之后才显示；未取得有效结果为“未知”。新一局／新节点先清除旧排名，不能沿用其它节点或上一轮的名次。预热参与实时参考榜，赛后补传保留但不入榜，以服务端首次收件时间为准。
- 跳过节点的完整记录可以上传留存，但服务器不把它列入节点及总成绩参考排名。

## 时序与故障边界

原有节点判定固定结果之后，仅发布标量和节点快照。该路径不做 HTTP、文件 IO、哈希、序列化或等待后台任务。所有网络及磁盘工作由单一后台循环处理；至多一个在途请求，节点查询合并为最新快照。

GET 最多等 3 秒、POST 最多 5 秒，等待均不在 UI／计时线程。查询结果绑定比赛、赛道、路线、轮次及节点；重置、换核心或设置后忽略过时响应。设置页和独立窗口低频刷新。断网、超时、响应异常和重试不产生任何显性提示，标题、排名窗口和设置页均不显示失败／重试状态或待传数量；窗口只保留当前节点已成功取得的排名；新节点和新跑次为“未知”。

通关生成一次 UUID，先落盘固定消息，再发 POST；重试使用原消息和 ID。暂时失败按 10／30／120／300 秒退避并遵守 Retry-After。永久格式／权限／冲突错误保留记录，设置页可安排重试；不能用重试绕过本机已确认的不合格状态。游戏数据及云存读档协议均不改动。

正常关闭先取消 HTTP，后台保存已接收的通关记录后退出；不等 HTTP 超时。PAL 退出后仍可完成已接收记录的上传；重新启动计时器后，连接启用了同一比赛配置的游戏才继续该比赛补传。磁盘不可写时保留窗口并在设置页说明，不悄悄丢弃成绩。两台机器的独立窗口、OBS、实际两小时跑次压力及真实服务器由人工验收。

## 本机文件与设备身份

本机数据根为 `%LOCALAPPDATA%\PalTimer\Competition-v1`：外观偏好、按服务隔离的加密设备凭据、outbox、receipts、network.log；这些个人数据不写入游戏配置、不随覆盖包分发。上传权限不取自此处的旧 `Enabled` 或服务器字段。网络日志只记录操作、HTTP 状态及尝试次数，512 KiB 轮转一份，不记录凭据、HWID、响应正文或 URL。服务器通过成功接收的记录更新成绩。

游戏契约为 `palmod/common-tools.v1.json` 内的可选 `competition_upload`，schema 为 `PAL98.CompetitionUploadSettings.v1`，其 `xiaorou` 包含 `enabled/server/event_id/ruleset_id`。字段随现有工具配置快照保存、切换、导入和锁定；不新增 DLL 配置文件白名单，不改变旧锁签名。地址只能是 HTTPS origin（仅 loopback 测试允许 HTTP），不包含路径、用户信息、查询或片段。缺失、损坏或无法验证时联机关闭，本地计时继续。

此次首次引入比赛 HWID，为 `win-` 加 Windows MachineGuid 的域隔离 SHA-256。计时器现有代码没有可复用的公开 HWID 接口；不借用云 ID，不枚举硬件／MAC、不上传原 MachineGuid、机器名或路径。系统重装、克隆或换机仍需主办方确认并绑定，不宣称 HWID 不可伪造。

凭据用系统随机源生成，DPAPI 当前 Windows 用户加密；HTTP 使用 Bearer 和 `X-PAL-HWID`，设备标识不放 URL。生产服务器只允许 HTTPS，不关闭证书校验，不跟随重定向。仅本机 loopback 测试允许 HTTP。凭据不写 OBS、普通成绩文件或日志；重置凭据由主办方独立处理。
