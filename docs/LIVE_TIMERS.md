# 实时联机与裁判视图（3.37.7.11 起）

计时器显示版本仍为 3.37.7，当前内部文件版本 3.37.7.12。需要配套
PalCompetitionAuth.dll、PalCompetitionRegistration.public.json，以及支持
PAL98.TimerLive.v1 的 PalServer。忽爷云 ID 和 PalCloudLib.dll 保持原样。

## 玩家看到什么

游戏已开启联机时，主界面玩法标题及 Windows 窗口标题末尾显示：

- `[连接中]`：首次握手尚未完成。
- `[已连接:1042]`：服务器已确认当前会话的近期心跳，1042 是示例短 ID。
- `[连接失败]`：心跳过期、认证未通过或服务器尚不支持；本地计时照常。

未开启联机时不增加后缀。已有长标题换行方式保持。短 ID 对应当前计时器实例，
按 P 重启游戏、Reset 或断线重连保留；重新打开计时器产生新实例。
“联机与排名”窗口显示详细原因及原有激活状态。没有新增按钮，原云 ID 按钮不改。
服务端仍要求当前 EXE 构建被批准，不能凭设备已绑定或收到排名查询冒充已连接。

## 裁判查看哪里

PalServer 管理后台的计时器页面新增“实时计时器”；独立裁判入口为
`/api/v1/timer/admin/live/`，沿用管理员认证。可以跨搜索结果多选最多 12 个短 ID，
点击“观看所选”后每位选手一列、每个节点一行；表头显示玩家名、当前累计时间和状态。
相同配置编号及路线按节点身份对齐，不同玩法分组查看。列顺序固定，窄屏横向滚动。
刷新中断保留最后收到的数据并明确标记；Reset 清空对应旧轮次，不影响其它选手列。

同一人的多个设备按已有 player_id 归并成绩，实时实例分开显示。未绑定名字明确
显示未绑定，不根据名字自动合并。视图不公开 HWID、IP、设备凭据或会话 token。
后台手工插入的通关成绩不会出现在实时列表里。

这是一份实时观察，不是录像审核结论，也不证明每个受控进程都无法被修改。
当前跑次更新独立于完整成绩：不把未通关的累计时间插入总榜；完赛仍使用原有完整
签封和提交协议，日常／比赛资格及普通／硬核规则保持。

## 时序与开销

- 本地计时完成本次处理后，仅发布内存数据；累计时间最多每秒发布一次。
- 单后台任务每五秒发送一次轻量状态，过节点立即安排后台更新；节点请求同时取得
  完整最佳线、个人节点参考和总榜摘要，成功后不再重复发送同一 GET 查询。
- 哈希和 RSA 会话证明只在后台建立连接时执行；心跳使用受限、短期会话 token。
- 所有 HTTP 串行，超时三秒；失败按 5/10/20/30/60 秒上限退避并遵守 Retry-After。
- 二十秒没有有效 ACK，标题及后台显示连接中断；不会让上次成功一直表示在线。
- 停顿或缺少最新本地观察时不继续推算计时；PAL 关闭显示等待游戏。离开网页或隐藏
  网页时停止轮询，恢复可见再刷新。
- Reset、切核心、切服务器、换跑次均隔离旧响应；实时状态只保留最新快照，不积累
  每五秒一份的历史日志。正常心跳不逐次写本地日志。

## 升级与验收

一起覆盖 EXE、认证 DLL 和公开登记资料；服务器先部署对应代码。发布者信任关系沿用，
新 EXE 自动登记为待批准构建，管理员需批准实际新哈希。原云 ID 仍需忽爷独立激活。
不能用旧构建的批准代替本次构建。

自动验证包括内存发布不等网络、单请求、标题租期、节点回传、Reset、P 重启观察、
旧服务器、撤销和错误 ACK，以及真实原生证明至隔离服务器的会话和完赛上传。
测试数据不是真实玩家成绩；真实云服务、完整速通、OBS、AMD、Win7 和 Windows ARM
需要对应环境验收。
