# 云存档接力的随机技能状态与时间

2026-10-14：此修复纳入计时器 3.38.2，并随 PALDLL / 配置工具 1.7.2.2（显示 v1.72）升级包提供。实机双向云存档接力仍需玩家验收。

2026-10-14 菜单入口补修：DX9 与自动核心个人云存档上传不再调用成绩资格校验，接力导入后可继续上传；导出时捕获的进程与跑次仍必须一致。成绩、比赛与硬核未验证标记、文件格式、RPG 绑定哈希及事务保护均保持。版本沿用 3.38.2，EXE、Online、Auth 与公开登记 JSON 成套重建。

## 行为

PALDLL 已把战后随机技能运行状态保存在 `N.RPG.pal98-random-skills.json`，旧计时器的完整 RPG 接力包漏传了它。`SRPGSaveBundleTransport` 现在同时携带种子、战后抽取序号、16个角色的初始化标记与遗忘队列。无需修改云服务器，仍原样传输 SRPG `.bin`。

- 普通、DX9、不欢乐及自动 DX9 核心均可恢复完整存档包；发送端使用 PAL.dll >= 1.6.2.0 时携带完整 RPG 与附属状态。
- 发送时验证状态绑定的 RPG SHA-256 和源槽号，等待 PALDLL 在 RPG 后写完状态；有效状态即使磁盘开关已关闭也会保留，因为游戏可能仍沿用启动时配置。读取不到配置时拒绝导出，不能把读取失败当成关闭。
- `[extra] RandomLevelUpSkills=1` 且 `RandomSkillVictoryAdd=1` 时必须具备完整状态。旧 `RandomSkillVictoryLearnAndForget` 的缺键迁移与 PALDLL 一致；明确的新键优先。关闭功能时可忽略与当前 RPG 不符的旧残留。
- 接收时保留全部运行状态，仅把 `save_file` 改为目标槽 `1.RPG`，再次校验后与 RPG、扩展角色、飞行旗一同提交。任一写入失败回滚整个文件组，旧文件保留时间戳备份。
- 恢复不受接收方配置 UUID、玩法识别、计时分类、随机技能开关、PALDLL 版本、Profile 或固定角色库身份限制。保留 RPG/附属状态的内部格式、绑定哈希、槽号及事务校验；损坏数据不写入。接收方配置、PALDLL、Profile 和固定角色库保持原样，因此能恢复文件不等于不同内容资源能够正确运行该存档。`RandomSkillRerollOnLoad=1` 仍按玩家配置在读档时重新随机；要继续同一随机序列应保持它关闭。

原有时间传递逻辑保持：SRPG 内的 `TimerStr` 恢复发送方累计用时、重启空闲时间、已完成分段和当前节点。A、B 互换后，各自从收到的那份进度继续，不把接收方原有用时叠加进去。导入后保持计时器开启，按提示重启 PAL.exe，读“进度一”，在游戏前台按 F9 恢复计时。

所有接力导入均标为未验证；成绩上传、排名与硬核资格不会因恢复而获得。个人云文件会话可在未识别配置和成绩无效时使用；无效时清除普通成绩载荷及覆盖缓存，不停止文件上传/下载。断网不停止本地时钟，旧上传协议降级继续显示“不完全连接”。

## 新旧版本边界

完整存档包 schema 升为 `PalTimer.PAL98SaveBundle.v2`，新增随机状态载荷和校验值，明确区分“没有状态”和“旧包不知道状态”。双方都需要使用包含此修复的计时器；旧版完整包读者会拒绝 v2，避免悄悄丢弃随机状态。

新版在任意接收方配置下允许读取 v1；它没有记录的种子和队列无法补算，若要延续原序列，应由发送方在原进度重新存档并导出新版包。读取 v1 时不触碰未知随机状态；v2 明确为空时，目标旧状态先备份再清除。

## 验证与回滚

运行 `tests/run_srpg_save_bundle_tests.ps1`：Release x64 构建、真实 SRPG 序列化、A/B 双向及往返、完整16队列、数值边界、旧版本兼容、延迟写入、格式/哈希/槽号拒绝、5个提交边界逐一故障回滚。另用当前 PALDLL 的真实 C++ 解码器读取计时器生成的状态，并拒绝错误槽号或 RPG 哈希。计时宿主调用实际普通、不欢乐、DX9/自动核心的导出与恢复代码，覆盖不同累计时间、21分段及节点互换、暂停、进程清理、重启耗时、F9回调与下一节点续时；仅将实机附着、游戏就绪和前台状态替换为合成输入。测试不访问云服务或玩家存档。

新增 `tests/run_cloud_save_menu_tests.ps1 -TimerAssembly <Pal98Timer.exe>`：直接定位并执行构建产物中 `InitUI` 注册的真实上传后台回调，经过 `GForm.OUpload` 与真实云会话队列，仅替换网络客户端及可见 UI 完成通知。普通 DX9 与自动核心均覆盖导入后再次上传、跑次改变、进程更换/退出、传输失败保留导出文件；同时断言累计时间及成绩/比赛/硬核未验证状态不变。测试不启动 PAL.exe、不访问真实网络，也不替代 A→B→A 实机验收。

真实双机云上传/下载、PAL.exe 重启与继续下一场战斗仍需玩家验收：检查收到的累计时间/节点、第9次酒神删除对象，以及下一次战后抽技/遗忘延续发送方序列。

源码回滚应同时恢复本次云会话、存档传输与各核心的恢复入口，并重新构建配套计时器及认证组件。若要恢复一次导入前的文件，应退出游戏，从同一批 `.paltimer-backup-*` 恢复 RPG 和全部附属状态；不要混用不同批次。回退计时器后不能读取 v2 包，先保留原包。
