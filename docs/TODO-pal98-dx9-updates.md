# TODO: 仙剑98 / 仙剑98DX9 速通计时器更新计划

创建日期：2026-05-09  
作者背景：othercat 主要维护 `PALDLL_DX9` 新补丁；本仓库是仙剑系列速通自动计时器。  
当前目标：先沉淀需求和开发线索，后续再由 AI 或人工分批实现。

## 背景摘要

- `仙剑98DX9` 配置主要服务于 `PALDLL_DX9` 对应的仙剑98新补丁。
- 计时器核心原理是读取仙剑98进程内存，依据地图、坐标、物品、战斗敌人等状态判断节点是否完成。
- 当前节点推进是顺序制：只有当前节点满足 `Check()` 才会进入下一个节点。
- 通关条件应以最终击败拜月为准，拜月血量为 0 时主计时结束。
- `仙剑98DX9` 的改动原则上也应同步到 `仙剑98` 和 `仙剑98不欢乐模式` 配置，避免三个高相似内核继续分叉。
- 当前最低系统要求是 Win7 SP1。
- 当前默认编译环境应使用 VS2026，编译目标为 `Release|x64`。
- 由于当前调用的 `PalCloudLib` 相关库文件只有 64 位版本，已拿掉 32 位编译目标，后续不要再默认恢复 x86 目标。

## P0: 主计时在部分电脑上不能居中

现象：

- 主界面截图 `snapshots\01.png` 下方最大的 `00:00:00` 是主计时。
- 在部分用户电脑上主计时视觉上不能居中。

初步定位：

- `GEX.BuildRects()` 当前将主时间和厘秒拆为两个区域：
  - `rcMainTimer`
  - `rcMainTimerMS`
- `DrawMainTimer()` 使用 `GLayout.sfFC` 绘制 `HH:MM:SS`。
- `DrawMainTimerMS()` 使用 `GLayout.sfFN` 绘制厘秒。
- 当前布局通过固定左边距、固定右侧厘秒区域估算，可能受 DPI、字体 fallback、系统缩放、字体度量差异影响。

建议实现方向：

- 把主计时整体视为一个视觉组合来居中，而不是分别让 `HH:MM:SS` 和厘秒依赖固定矩形。
- 使用 `Graphics.MeasureString` 或 `TextRenderer.MeasureText` 以当前字体测量：
  - `HH:MM:SS` 宽度
  - 厘秒宽度
  - 反作弊 `*` 宽度
- 根据总宽度计算组合起点，使整体中心对齐窗口或主计时可用区域中心。
- 保留现有样式设置、描边、双击区域和局部刷新逻辑。

验收点：

- 100%、125%、150% Windows 显示缩放下，主计时视觉居中。
- 不同字体、字号、窗口宽度下，主时间和厘秒不重叠。
- `*00:00:00` 反作弊状态也居中。
- 简版小窗口不出现文本裁切。

## P0: 游戏关闭后仍反复提示 DX9 窗口句柄无效

现象：

- 仙剑98关闭后，计时器有时仍不断提示：`请使用仙剑98 DX9移植版！窗口句柄无效`。
- 该问题只在固定几个人电脑上偶发。

初步定位：

- `仙剑98柔情DX9.GetPalHandle()` 中当 `Process.GetProcessesByName("Pal")` 找到进程，但 `MainWindowHandle == IntPtr.Zero` 且超过宽限期后，会设置 `cryerror`。
- 风险场景：
  - 进程退出窗口已销毁，但进程对象短时间仍存在。
  - 多 Pal 进程或旧 PID 状态未及时重置。
  - `cryerror` 没有在游戏消失或状态恢复时清空。

建议实现方向：

- 在设置“窗口句柄无效”前增加更严格的存活和主窗口校验：
  - `HasExited`
  - `MainWindowHandle`
  - `PID` 是否仍匹配
  - 必要时 `Refresh()` 后再读窗口句柄
- 游戏关闭时应清理：
  - `PalHandle`
  - `GameWindowHandle`
  - `PalProcess`
  - `PID`
  - `GMD5`
  - `DX9Version`
  - `InitialDetectionTime`
  - `HasConfirmedDX9`
  - `cryerror`
- 区分“启动过程等待 DX9 标题”和“游戏已关闭”：
  - 启动中可以静默等待。
  - 已确认过 DX9 后，如果进程/窗口消失，应停止读取并静默回到等待状态，不应弹错。

验收点：

- 关闭仙剑98后不再循环弹出窗口句柄无效。
- 正常启动 DX9 版本仍能识别。
- 非 DX9 版本或标题不匹配时仍能给出一次明确提示，但不刷屏。
- 多开 Pal 时仍能稳定选择正确进程或给出合理提示。

## P0: 支持跳图路线的非顺序节点推进

现状：

- `TimerCore.Checking()` 只检查 `CheckPoints[CurrentStep]`。
- 当前节点不满足时，即使后续节点已经满足，也不会跳过。
- 跳过节点测试截图见 `snapshots\02.png`。
- 现有跳过节点颜色效果不好看，暂时不要做颜色区分。

需求：

- 对跳地图玩法，允许后续节点先满足。
- 如果没满足当前节点但满足了后面的节点，应直接推进到对应节点之后。
- 只做自动跳节点逻辑；被跳过节点先沿用现有普通显示，不新增特殊颜色。
- 最终击败拜月仍应结束计时。

建议实现方向：

- `TimerCore.Checking()` 从当前节点开始扫描后续节点：
  - 优先检查当前节点。
  - 当前不满足时，可向后查找第一个满足的节点。
  - 中间未满足节点按跳过处理，但不改 UI 颜色。
  - 命中的后续节点标记为完成，并推进到下一节点。
- 建议提供开关，至少先仅对 `PAL98DX9`、`PAL98`、`PAL98UNHAPPY` 启用，避免影响其他游戏内核。
- 对“拜月血量为 0”这种终点条件应允许全局优先识别。

验收点：

- 正常路线行为不变。
- 跳过早期节点后，后续节点能触发并推进。
- 被跳过节点不出现 `snapshots\02.png` 中那种难看的特殊颜色效果。
- 区间时间差、预计通关、导出成绩和插件事件不崩。
- 手动 `Jump()` 与自动跳过状态不互相污染。

## P1: 节点快慢提示音效

来源：

- 需求截图见 `snapshots\03.png`。
- 目标不是固定音效，而是支持玩家按几种情况自行配置音效。

需求：

- 当节点完成后，根据成绩快慢播放不同提示音。
- 至少支持以下几类触发条件：
  - 分段快了播放一种音效。
  - 分段慢了播放一种音效。
  - 总时间快了但当前分段慢了时，可播放独立音效。
  - 总时间慢了但当前分段快了时，可播放独立音效。
- 音效最好支持外部文件，例如 mp3，方便玩家放自己的提示语音。
- 需要有配置入口，可以设置每种情况对应的音频文件，也可以关闭某类音效。

建议实现方向：

- 在节点完成时复用已有区间差和总时间差计算：
  - 总时间快/慢：当前节点 `Current` 对比该节点 `Best`。
  - 分段快/慢：当前区间耗时对比最佳线相邻节点区间耗时。
- 增加音效配置文件或扩展现有配置，保存不同触发条件的音频路径和启用状态。
- 播放方式优先选择对 Win7 SP1 友好的方案；如使用 mp3，需要确认 .NET Framework 4.0 / Win7 环境可用。
- 音效播放应异步或非阻塞，不能影响计时器 UI 和节点推进。
- 文件不存在、格式不支持、播放失败时不要弹窗刷屏，可静默跳过或只写调试信息。

验收点：

- 节点完成时能按“分段快/慢”和“总时间快/慢”的组合选择正确音效。
- 用户能替换为自己的外部音频文件。
- 未配置音效时行为与当前版本一致。
- 连续快速跳节点时不阻塞计时器、不重复卡住播放。
- Win7 SP1 64 位环境可正常播放或安全降级。

## P1: “土”的检测失效且需要实时统计

现状：

- `仙剑98柔情DX9` 和 `仙剑98柔情` 中 `MaxTLF` 对应 `EarthPaper`。
- 战斗开始记录 `0x47` 土灵符，战斗结束时累加。
- 实时战斗显示目前只更新火、血、剑、夜行衣：
  - `CurrentBattleHCG`
  - `CurrentBattleXLL`
  - `CurrentBattleLQJ`
  - `CurrentBattleYXY`
- “土”没有对应实时临时变量，显示只依赖 `MaxTLF`。
- “土”的显示机制应与“甲”一致：默认不显示，只有偷到后才显示。

建议实现方向：

- 增加 `CurrentBattleTLF`，逻辑与火、血、剑、夜行衣一致。
- `BattleBegin()` 继续记录 `0x47` 初始值。
- `Battling()` 中实时更新 `CurrentBattleTLF = biw.GettedCount(0x47)`。
- `GetMoreInfo()` 显示时使用 `MaxTLF + CurrentBattleTLF`，但仅当累计值大于 0 时显示 `土N`。
- 确认 `0x47` 是否仍是新补丁下土灵符物品 ID；如失效，按 PALDLL_DX9 / Pal98Robot 的物品读取结果重新校对。

验收点：

- 战斗中获得土灵符后，“土”数值实时变化。
- 战斗结束后数值固化到 `MaxTLF`，不重复累加。
- 未偷到土灵符时不显示“土0”。
- 读档、云存档、导出成绩中的 `EarthPaper` 保持正确。
- `PAL98DX9`、`PAL98` 和 `PAL98UNHAPPY` 行为一致。

扩展 `SoundConfig` 为每个 `SoundTriggerType` 保存 0-100 音量；打开/关闭提示音也各自保存独立音量。旧版 `sound_config.txt` 的 `启用|文件路径` 格式仍可读取，保存后升级为 `启用|音量|文件路径`。

播放时 MCI 路径通过 `setaudio <alias> volume to <0-1000>` 设置音量；MP3 的 Windows Media Player COM 回退路径同步设置 `settings.volume`。试听按钮使用当前行的音量。

## DONE: 跳图路线改为功能开关

非顺序节点推进从内核硬编码改为用户可控的功能开关。功能菜单新增"跳图路线(非顺序节点)"勾选项，默认不勾选（传统顺序模式），勾选后启用非顺序推进。

实现：`GForm.IsNonSequentialCheck` 字段 + `skip_node` 文件持久化（内容 `1`/`0`）。`TimerCore.Checking()` 改为读取 `form.IsNonSequentialCheck`。三个 PAL98 内核删除 `EnableNonSequentialCheck = true` 硬编码。

原因：mod 提前给物品（如水灵珠）会导致基于物品的节点被误触发，影响正常玩法。

## DONE: 水灵珠节点区分正常十年前剧情与跳过剧情路线

PAL98/PAL98DX9 的“水灵珠”节点改为“剧情标记结束 + 背包存在水灵珠”的组合条件。正常十年前路线使用补丁资源中唯一的“得到水灵珠”对话；回梦无痕等跳过十年前的路线使用回到大理祭坛后“糟．．希望灵儿不会有事才好”对话。开局或随机物品玩法提前持有水灵珠不会单独触发节点。

计时器连接新 PAL.exe 进程时只读取一次最终生效的 `SSS.MKF` 和 `M.MSG`，按 GBK 文本动态解析对话 ID，并要求对应 `FFFF` 脚本引用唯一；解析失败时节点保持未触发并给出提示。70ms 轮询只通过 `0x428000 -> p1 + 0x500 -> p2` 读取当前 8 字节脚本状态，再结合既有背包物品读取，不在热循环中访问资源文件。不欢乐模式本来没有水灵珠节点，因此未接入该逻辑。

## DONE: 最终通关音效配置

`SoundTriggerType` 枚举新增 `GameComplete`。`OnCheckPointEnd()` 中播放此音效。配置窗口自动多一行"最终通关"，用法与其他节点音效一致。

新增音效优先级机制：`GetPriority()` 返回优先级值（通关=30 > 总时间=20 > 分段=10）。`PlaySound()` 支持优先级中断——高优先级音效会停止当前正在播放的低优先级音效，低优先级不会打断高优先级。

## DONE: 云读档撞怪计数完整快照兼容

`PALCloud.dll` 没有单独的 `TotalMonsterCount`（撞怪总数）接口，但服务器会原样存取整个 SRPG `.bin`，其中 `TimerStr` 已携带该字段。PAL98、PAL98DX9、PAL98UNHAPPY 三个内核在导入时按字段存在性恢复：新 SRPG 有该字段就恢复快照值，旧 SRPG 缺少字段则保留当前本地计数。云读档和接力读档语义一致，不需要修改服务器或 `PALCloud.dll`。

## DONE: 暂停状态下操作存档后保持暂停

用户手动暂停后操作云存档/接力存档，存档完成后计时器自动恢复计时。已修复：在 `UI_SaveGameEx`、接力-接盘、云读档三处使用 `wasPausedBefore` 模式，操作前记录暂停状态，操作后仅在原先未暂停时才恢复。三个内核均已同步。

节点音效每行的勾选框即为实时启用开关，勾选后才在节点完成/通关时播放，配置通过 `sound_config.txt` 的 `enabled|path` 格式持久化。
