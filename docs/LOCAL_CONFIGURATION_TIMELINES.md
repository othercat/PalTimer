# 3.38.0 本地配置最佳线

DX9 自动玩法核心可以在玩法身份未知时保存本局为本地最佳参考线。无需服务器收录、联网或切换计时核心。它保存核心已经记录的时间和节点，不扩展未知改版的节点识别能力。

## 玩家使用

1. 使用配置工具应用配置并启动游戏，保持“仙剑98 DX9 自动玩法（实验）”核心。
2. 开局时计时器在后台读取当前配置，并固定本局归属。读取完成前主计时照常运行；退出游戏后不会重新读取后来切换的配置。
3. 点击“设置本次成绩为最佳”。保存成功立即更新参考值及预计通关；当前节点和主计时保留，只有玩家随后确认重置才重置。
4. 重开同配置会加载同一参考线。配置名称、音乐、窗口设置和逐局随机技能种子改变不新建时间线。不同配置 ID、玩法设置、速度、实际内容资源、普通／硬核及节点名称或顺序分开保存。
5. 如果配置不可读，选择“选择本地最佳线配置…”，从已保存归属中选本局配置，或输入名称新建。即使名称相同，新建归属也各自独立。取消选择或写入失败会保留当前计时。

从当前游戏的已选配置文件导入时，读取同一套生效设置。脱离游戏目录、非当前配置或无法解析生效设置的文件明确标记为“文件参考”，仅按该文件内容保存；下次需在列表中再次选用。它不能自动推断本机硬核覆盖设置。玩法已变更时应新建归属，不应手选旧玩法参考冒充同一配置。

## 存储与兼容

- 本地线：`Timelines/Configurations/<配置与玩法摘要>/best.json`。
- 可再次选择的配置归属：`Timelines/Configurations/profiles/`。仅保存名称、ID、摘要、路线及普通／硬核标记，不保存原始配置、设备凭据或密钥。
- 沿用计时器现有目录权限回退：可写目录就地保存，否则使用用户设置目录。支持长路径。
- 保存替换使用同目录临时文件和原子替换，旧线留下带时间标记的备份；替换失败保留 `.pending-*` 供恢复。
- 旧 `Timelines/<玩法身份>/` 文件保留。在运行时身份相同且尚无配置线时，可以作为只读参考。新保存写到配置线；“导入旧最佳线为当前玩法参考…”也不修改来源文件。
- 已有配置线优先于旧玩法线；运行时重新识别不会换掉已固定的配置归属。只有重置才开始新的本局配置选择。

## 认证边界

配置文件摘要检查用于区分本地参考归属，不授予配置签名信任或运行时认证。保存入口单独校验本地归属，不复用比赛成绩准入条件；本地文件明确标为参考，并将玩法、时序、硬核跑次的已验证标记设为 false。导入接力时拒绝本地配置参考，即使有人修改其已验证标记。当前跑次的联机证据、排名、比赛资格、硬核验证和普通 DX9 核心原有的保存条件不因本功能放宽。

## 实现与验证入口

配置归属组合包含唯一 ID、规范化后的实际配置、内容资源、节点路线及普通／硬核。仅明确的显示/音乐/逐局种子字段被排除，未知设置保留。当前配置选择遵循 `id + content_sha256 + storage_key`；有效文件使用共享 `ReadGamePath` 用户目录规则。Profile 跟随已选包及合法更新指针，检查描述文件并纳入实际资源，避免把被覆盖的根资源当作当前内容。未完成配置事务或读取期间修改时不固定不完整快照，改由玩家明确选择归属。

定向宿主：`tests/run_local_configuration_tests.ps1`，可通过 `-PresetDirectory` 只读检查旧包的 `.pal98config`。它覆盖未知核心真实校验失败时的本地保存、即时刷新、重开、配置区分、用户目录、写入失败、旧文件保留、开局异步读取、并发重置、Profile 和合成 PAL 进程目录读取。宿主不运行真实游戏，也不访问真实服务器。

发布前还应运行既有 gameplay、v165 timing、user settings、competition、live 和配套 online module 加载检查。玩家人工回归仍需确认：在实际未知玩法上完整通关后保存并重开、F9/P 重启、OBS 显示，以及新构建获批准后的联机情况。静态或宿主测试不等同于这些实机验收。
