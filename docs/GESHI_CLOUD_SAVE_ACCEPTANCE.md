# 隔世追凶云存档离线验收

2026-10-18，关联 [Issue #26](https://github.com/othercat/PalTimer/issues/26)、[#18](https://github.com/othercat/PalTimer/issues/18) 和 [游戏 #5](https://github.com/othercat/sdlpal-lostedit/issues/5)。用户当前的旧个人云 ID 未激活，本轮不进行线上文件传输；pallab.top 的榜单批准不等于旧个人云激活。

## 对象与方法

直接使用 r13 整包的实际发布程序集，不重编产品、修改版本或重新申请审批：

| 对象 | 身份 |
| --- | --- |
| Pal98Timer 3.38.3.0 | SHA256 `d03a99ddb2d2de4a6d27c3560573d71f623dd4df89da0296f34fe7bfdbb1c818` |
| 旧云登记所用 EXE MD5 | `6bd2e9574c3ee40701a899364c75a0f1` |
| 核心名 | `SDLPAL_GESHI_EASY` |
| r13 游戏 `50a6fe4` | SHA256 `bc017f3353b1af5aa2cb756b833baaa72c5e6454fe07eca481a75bf181bea081` |

宿主反射调用发布 EXE 的 `CloudSave/CloudLoad` 内层操作委托，经真实 `RunRelay → SavePackage/LoadPackage → GForm.OUpload/ODownload → CloudSessionRunner`。只有 `ICloudStepClient` 换为隔离目录中的文件存储替身；没有实例化真实旧云 SDK 客户端、读取云凭据或发送生产请求。两个真实 SDLPAL 诊断进程处理存读命令，游戏和计时器均来自包的副本。

```powershell
./tests/run_native_sdlpal_relay.ps1 -PackageDirectory '<r13 解压目录>' -Cloud
```

脚本只编译独立宿主，支持包内 `pal.exe` 或旧包 `sdlpal.exe`。宿主等待游戏真正回到允许存读的探索帧，不绕过原生保护。外层成功/错误对话框、编码输入校验及其 finally 接线未执行；清理调用使用同一产品 `TryDeleteTemporary`。因此这不是点击整个 GUI 或实际服务端往返的证据。

## 结果

`artifacts/native-relay-f0c57f57` 共 **100 项通过**，4 次上传调用、14 次下载调用，包括故意失败的调用；两个原生进程正常退出 0。每个下载负例都确认对应对象 key 实际到达传输层，避免把测试等待超时误当坏包拒绝。普通槽 1–5、源包存档均未改变。

不带 `-Cloud` 的原本地接力模式也以 r13 重跑，20 项通过、退出 0，证据 `artifacts/native-relay-38762eb2`。

- 两份原生存档经云包双向恢复：场景 227 / 金钱 31265 / 37.500 秒 / 节点 1，以及场景 93 / 金钱 9817 / 77.250 秒 / 节点 0，分别在另一游戏中恢复。已完成节点的 20 秒、节点状态、主窗口数据和区间显示一致，恢复后暂停；诊断/辅助资格仍保留。
- 上传对象使用 `geshi-<ID>-<32位随机码>.bin`，载荷含完整 RPG 字节、SHA256、计时及节点信息。上传的存档与原生确认文件逐字节一致。
- 未激活菜单禁用；`OUpload/ODownload` 在传输队列前拒绝，不读取/写入测试文件或调用文件传输。该检查不宣称真实应用完全没有初始化登记请求。
- 本轮模拟上传失败时未产生成功对象，当前游戏和暂停计时仍在。产品会删除临时 `.bin`；重新点云存档会重新导出，本轮验证重试得到完整当前状态。它不是保留失败包并原样重传的功能。
- 下载失败后可重试恢复。错误包身份、schema、校验和、Base64、计时核心/节点、截断 JSON、超大对象及传输中会话失效均被拒绝，当前游戏/计时不变，未向游戏发出 LOAD，也未覆盖保留槽。
- 正确校验和但内容截断的 RPG 到达真实原生校验后返回状态 4，当前游戏和计时不变；暂存用的 `250.rpg` 已更新，但原内容存在原子替换备份中。普通槽不受影响。

前三轮宿主调试证据保留：`native-relay-b62ff055` 未等 LOAD 后安全帧、`native-relay-75d804fa` 未单独捕获 `InvalidDataException`、`native-relay-cb82cf21` 未识别旧 JSON 依赖的错误类型；均已按实际生产行为校正测试，不改产品以满足断言。

旧 `System.Web.Script.Serialization.dll` 在截断 JSON 的错误路径缺少 `AtlasWeb.resources`，抛出 `MissingManifestResourceException`。该坏包仍在 LOAD 前失败，外层会捕获异常，但提示文字是技术性资源错误。此限制已记录，不将坏包拒绝称为错误文案体验通过。

若游戏已确认 LOAD、随后快照同步超时，游戏可能已载入而计时尚未替换，产品会保持暂停并要求核对；本轮未模拟该故障，不能概括为所有失败都保证游戏完全未变化。

## 激活后仍需实测

1. 两端使用同一 r13 引擎、资源、速度设置及节点规则，分别打开游戏和隔世核心，确认显示有效云 ID。不同电脑、PID 和安装路径不构成包身份；旧引擎/资源或不同节点规则仍会拒绝。
2. 用备份档开练习局，记下地图、位置、物品、金钱、计时和当前节点，点“云存档（隔世追凶）”，保留成功返回的编码。
3. 在另一台电脑运行相同包，点“云读档（隔世追凶）”，输入编码；核对游戏状态、计时和节点都恢复且暂停，按 F9 后能继续。检查普通存档未被覆盖。
4. 断网重试及不存在的编码应显示失败且不伪报成功；旧个人云存档服务权限、真实上传/下载及跨电脑往返取得证据后，才可记为线上通过。

本次仅添加测试和文档。没有更改计时、暂停、反作弊、路线、OBS、进程匹配或内存地址；PAL98/PAL98DX9/PAL98UNHAPPY 不需要同步产品改动。真实云激活与往返仍由 #18 / 游戏 #5 跟踪，完整路线和前置身位手感仍由速通高手验收。
