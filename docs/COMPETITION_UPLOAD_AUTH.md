# 比赛上传的独立构建激活

> 历史认证说明：下文对应 3.37.7.5 及之前的 `PAL98.TimerUploadAuth.v1`。3.37.7.6 使用 `PAL98.TimerUploadAuth.v2`，当前边界见 [联机与排名](TIMER_ONLINE_3.37.7.6.md)。旧签封保留原字节，不转换或补签到新榜。

显示版本 3.37.7；本次内部版本 3.37.7.5。忽爷的云 ID、PalCloudLib.dll
和云存读档协议完全独立，不读取云 ID 来授予 PalServer 上传权限。

## 玩家行为

比赛设置页单独显示“比赛上传：已激活”“未激活，仅本地保存”或首次尚未取得
确认的“仅本地保存”。网络失败、超时和重试不显示提示；不改变标题、OBS、
游戏计时、暂停及已有合法性规则。网络失败保留上次确认状态，但服务端每次上传
都重新核验权限；本机显示不是授权凭据。未激活仍可以查询节点参考排名。

正常通关先在后台生成原始成绩签封，再写入本机 outbox。服务器未批准这个
生产构建时不 POST 成绩，五分钟后再次检查。该构建以后获准，可自动补传原签封。
同一 run ID 始终使用原成绩，不能更换生产版本。新版只转交旧签封，不补签旧记录。
3.37.7.0 的无签封记录、组件缺失期间的记录始终保留本地。它们仍可本地查看，
不能通过“后台重试”获得签封。赛后补传沿用服务器首次收件时间的阶段规则。

## 组件和服务端合同

`PalCompetitionAuth.dll` 是配套原生 x64 私有组件，放在计时器 EXE 旁。公开计时器
只包含窄 C ABI 适配器，没有生产签名密钥、一般签名接口或绕过开关。组件从当前
进程定位真实 EXE，核对冻结 SHA-256，并自行读取域隔离 HWID；调用方不能传入
另一份官方 EXE 代替宿主。组件从应用目录加载，不依赖当前工作目录。

本次支持完整签封自动玩法的 `PAL98.TimerCompetition.v2` 字段，外层认证合同不变。计时器 EXE 和认证 DLL 成对冻结；服务端只需要公开登记材料中的 EXE 哈希、组件哈希、版本、公钥及后续批准，不部署认证 DLL，不接收私有源码或私钥。旧签封继续保留原字节，不回填硬核资格。

`PAL98.TimerUploadAuth.v1` 使用 RSA-2048 / PKCS#1 v1.5 / SHA-256。
签名输入为以下字段的 UTF-8、LF 分隔、含末尾 LF；字段禁止换行。服务器严格
拒绝重复 JSON 字段、未知字段和非规范 base64，不能先重写消息再验证。

成绩签封：protocol、`run`、key_id、timer_exe_sha256、timer_version、
component_sha256、server_origin、event、hwid、run_id、原成绩字节的 SHA-256。
原成绩是旧核心的 `PAL98.TimerCompetition.v1` 或自动玩法核心的 `PAL98.TimerCompetition.v2` 原始 UTF-8 JSON，通过 payload_base64
封装；原主时间与末节点分别保存，三赛道规则不变。

上传证明：protocol、`request`、key_id、timer_exe_sha256、timer_version、
component_sha256、server_origin、event、hwid、challenge_id、nonce、
原始签封 JSON 字节的 SHA-256。

在原比赛 API 路径下新增 GET `auth/status`、POST `auth/challenges`。状态查询
本身不能授权上传。挑战存活 120 秒，单次使用，绑定设备、构建、目标和消息。
POST `runs` 接受 `{protocol,sealed_run,proof}`，后二者是对应 JSON 原字节的
base64。服务端在同一事务中重新检查生产及上传构建批准、校验两份签名、消费挑战
和写入成绩。旧的明文 POST 必须返回 `auth_required`，没有兼容上传旁路。
`build_not_approved` 是待批准状态，不能被客户端永久丢弃或频繁重传。

管理员只登记公开验证密钥、EXE SHA-256、组件 SHA-256 和完整版本，默认未批准。
批准/撤销有审计。原设备凭据、HWID 绑定和云 ID 均不能替代这个权限。旧服务器
没有认证接口时，新客户端只保留本地成绩，不回退旧明文上传。

## 构建和验收

先冻结 EXE，再由私有组件工程为该 EXE 构建配套 DLL。玩家包只包含所需二进制；
源码、私钥文件、生成头文件、对象文件和 PDB 不进入玩家包或公开仓库。
公开登记 JSON 单独交给主办方。每次 EXE 字节变化都需要新匹配组件、比赛后台登记
和忽爷的云激活登记；两个服务器互不代办。

后台执行所有哈希、签名、序列化、磁盘及网络工作；节点回调只发布原有标量快照。
原生组件没有驱动、提权和 CLR 依赖，目标为 Win7 SP1 x64；Windows ARM 使用系统
x64 模拟。目标系统、OBS、真实云服务和生产服务器结果需分别实测。

这属于用户态的改版阻力，不是硬件远程证明。具有调试能力的攻击者仍可能修改
内存或提取分发组件中的密钥。密钥按构建隔离、可撤销；不宣传绝对防作弊。
