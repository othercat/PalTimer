# 联机模块与成绩审核（3.37.7.13）

## 2026-10-04：1.0.0.1 锁配置兼容修复

EXE 继续使用 3.37.7.17 原字节，SHA-256 `e69e0c8625812532b54faeb1f849fe822e64fff9afb8aa3aa44bc0fc1fb3f286`。更新 `PalTimerOnline.dll`（1.0.0.1）、匹配的 `PalCompetitionAuth.dll` 和 `PalCompetitionRegistration.public.json` 三件套。原云 ID 的 EXE 激活不变；独立联机后台仍须批准新的组件组合。已信任的发布者公钥无需重新登记。

原因：联机工程链接了 `TournamentLockInfoReader.cs`，原包却保留了 1.0.0.0 旧二进制。EXE 已支持 v1.71 锁，联机组件仍拒绝同一份锁，随后被笼统显示为“联机未开启”。当前修复沿用签名、快照、资源身份和版本组合校验，不通过忽略锁或读取未签名文件来启用联机。失败原因仅在设置窗口显示；普通关闭联机、标题、OBS 和本地计时行为保持。

发布验证必须覆盖实际配套二进制：`tests/run_online_module_tests.ps1 -TimerDirectory <冻结计时器目录> -OnlineDll <候选联机DLL> -AuthDirectory <配套认证目录>`。检查 v1.68／v1.70／v1.71 有效锁、损坏签名、资源不符、混合／未知版本、旧锁无服务器快照以及未锁配置只参与日常榜。不能只测试 EXE 内的锁读取器或用重新编译源码的单测代替交付 DLL 验证。

显示版本仍为 3.37.7。EXE 文件版本为 3.37.7.13，首版 `PalTimerOnline.dll` 为 1.0.0.0，宿主接口为 API 1。本次不修改 PAL.dll、配置工具、PalCloudLib.dll 或旧最佳线。

## 模块边界

- EXE 保留计时核心、游戏状态读取、节点判断、玩法证据和原云 ID 功能。`OnlineHostContract.cs` 定义只读值接口，不传递 TimerCore、Process 句柄或可变游戏对象。
- 联机 DLL 负责配置读取、JSON 合同、队列、签封调用、登记、HTTP、退避、实时心跳、排名设置和 OBS 窗口。后台单 worker 串行处理；节点仅发布值快照，不进行 IO、哈希、签名或等待网络。
- EXE 在后台从自身目录读取 `PalCompetitionRegistration.public.json`，用内嵌的发布者公钥验证 Candidate.v2 签名及 EXE、Online、Auth 三份文件。持有只读共享文件直到退出，不支持运行中替换。
- 组件缺失、签名/哈希错误、接口不兼容时不加载联机。本地计时继续；只在主动打开“联机与排名”时说明组件问题。
- 私有 PalCompetitionAuth.dll 独立校验实际宿主和同目录 Online DLL，绑定整份成绩和一次性挑战。私有项目、密钥、生成头、对象文件不得进入此仓库或玩家包。

未来兼容 API 1 的联机变更可只重新编译 Online DLL、匹配 Auth DLL 和公开登记文件，EXE 字节保持不变，因此无需重复登记忽爷 EXE 哈希。联机后台仍需批准新的完整组合。API 不兼容、计时核心或宿主变化仍须更新 EXE。未批准的组合只保留本地记录；原云 ID 激活与联机批准互不替代。

## 上传与审核

新产生的成绩使用 `PAL98.TimerOnline.v2`，上传签封外层仍为 `PAL98.TimerUploadAuth.v2`。旧 v1 签封按原字节补传，不转换或重新签封；没有原始签封的历史记录不补认证。

v2 保留原节点顺序、节点状态、主时间、末节点时间、玩法和硬核事实。增加 `observations`，记录开局/完成观察、初始事实以及途中观察到的问题。跳过、未完成、乱序、未知玩法、证据不足、途中变更等由服务端判定待审，不在客户端按入榜条件拒绝签封。恢复原设置不能清除已观察到的途中变更。

格式和容量限制继续有效：1–256 个唯一节点、时间在 0–86400000 毫秒内、固定合同字段、受限文本和 64 KiB 成绩上限。未知事实为 null，不构造有效身份。新服务器能力经设备回复确认；旧服务器不支持 v2 时保留原签封并低频重试，不删字段降级。

服务端分别保存签封有效、人工审核和入榜资格。正常已认证成绩可自动入榜，异常成绩进入待审。管理员必须填写原因；分类不明确须另行裁定配置/路线/模式。批准缺节点成绩可进总榜，但缺失节点不参加节点比较。联机审核与录像审核独立。

## 按 P 重启

PAL98、DX9、不欢乐与自动玩法核心使用原有单调秒表累计空闲时间。新进程出现、窗口出现、运行时尚未就绪均不能结束重启空闲阶段；直到同一安装的进程恢复有效游戏状态才停止。PID、创建时间和实际路径用于区分进程。此修改不把空闲加进主表，也不增加固定惩罚，保持暂停、接力、完成冻结与 Reset 语义。

## 构建与更新

构建整个 `Pal98Timer.sln` 的 `Release|x64`；框架目标 .NET Framework 4.7.2。按 EXE → Online DLL → 匹配私有认证 → 发布者签名登记顺序冻结。只构建兼容模块时使用 `/p:BuildProjectReferences=false` 并复核原 EXE SHA-256 未变化。

覆盖时完整替换四份文件：Pal98Timer.exe、PalTimerOnline.dll、PalCompetitionAuth.dll、PalCompetitionRegistration.public.json。现有设置、设备凭据、最佳线、队列不替换。回滚同样恢复完整组合；旧服务器可能不支持新待传记录，仍保留本地文件。
