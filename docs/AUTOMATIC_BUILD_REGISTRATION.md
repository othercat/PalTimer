# 自动登记待批准构建（3.37.7.10）

显示版本仍为 3.37.7。计时、节点、暂停、最佳线、忽爷云 ID、排名遮罩和通关上传时机保持不变。

## 玩家使用

将同一发布批次的三个文件放在计时器目录：

- Pal98Timer.exe
- PalCompetitionAuth.dll
- PalCompetitionRegistration.public.json

第三份文件只含公开资料及发布签名，计时器自动读取并上报。玩家不需要打开、
编辑或提交它到后台。它不能激活其它 EXE 或认证 DLL，也不含私钥。

当目标游戏配置启用联机、服务器支持自动登记且当前构建尚未批准时，后台自动提交候选。
管理员批准后，计时器在下一次低频检查时获知，通常不超过五分钟。
未批准仍正常计时并保存本地签封；批准后沿用原有补传。网络故障只记本地日志，
不会出现在标题、OBS、排名或阻塞弹窗中。

这项批准与忽爷云 ID 激活相互独立。新 EXE 仍需在忽爷云服务单独登记。

## 服务器首次准备

在 PR #12 后台“构建批准 → 发布者公钥”中，从可信发布渠道取得并核对
publisher.public.json，只登记一次。以后每个新构建的资料由客户端自动上报，
管理员只需核对该版本的完整哈希并点击批准，不再手工导入 registration.public.json。

发布者公钥是固定信任入口；不能自动相信玩家提供的公钥。服务器验发布签名之后
仅登记待批准候选，绝不自动授予上传权限。旧手工登记与旧批准构建继续可用。

## 兼容与性能

- 不改变 Auth.v2 成绩签封或 Online.v1 成绩。新增可选 PAL98.TimerBuildCandidate.v1。
- 服务器 auth/status 未声明支持时不发送候选，保留旧的本地计时与上传行为。
- 缺少或损坏公开资料时不伪造候选，不影响原来已获批准的构建。
- 程序先由原生组件核对实际宿主 EXE 和组件，再匹配公开资料，不能指定另一个文件冒名登记。
- 公开资料最大 16 KiB，后台只读取并缓存一次；不再为此读取整份 EXE 或扫描游戏资源。
- 请求三秒截止；失败至少五分钟后退避，最长一小时，遵守 Retry-After；本进程成功后不反复登记。
- 使用既有单后台工作线程，节点入口只发布轻量状态，永不等待登记、网络或文件。
- 候选响应不是激活结果。正式状态及每次上传继续校验服务端批准，重复登记不能恢复撤销。

更新后需同时保留新 EXE／DLL／公开资料。回退时恢复原 EXE 和 DLL；旧客户端忽略
新公开资料，不改写旧签封、时间线或配置。服务器协议与审核详见 PalServer
docs/18-timer-build-candidates.md。

本地合同及合成成绩测试不代替真实云服务、管理员生产部署、完整速通、
OBS、实物硬核、AMD、Win7 或 Windows ARM 验收。
