# SDL 维护版加减速与存读档规则

2026-10-27，Refs #39；替代此前按开局速度分类的规则。适用于隔世简单、梦幻 2.2.2 普通/高难、梦时空 3.9x 高难。

同一内容资源、玩法效果和路线下，开局速度和途中加减速均使用同一配置、同一本地最佳线类别和榜单。配置事实为 family、profile、content 及四项资源哈希，加上启用的吴强、怪物突脸、隐形和重生规则；五项速度事实不进入新配置摘要。实际初始/结束速度仍保留在签封观测中，服务器不会回填或伪造默认速度。

同一进程、本轮已开始计时、资源和引擎身份不变时，普通游戏读档（包括死亡后读档）保持已累计时间和已完成节点，重新绑定战斗事件游标，不因此丧失成绩资格。存档自身不重置计时。换进程、重新开局、晚启动计时器、丢失事件、资源或引擎变更仍需明确处理；人工改节点、导入计时器时间线、接力或云时间线保留原辅助跑次语义。F9、失焦及已有暂停选项不变。

新格式使用服务端能力 `sdl-content-effects.v1`；服务不支持时，初始化和待上传记录保留待处理，不转换为旧格式。历史 12/15 键签封和待上传字节保留，服务端管理员可以明确把同内容同玩法的旧速度配置加入同一榜单；不自动公开、改写历史摘要或合榜。本地旧 PB 文件保留，不猜测和覆盖旧最佳记录。

不改变 PAL98、PAL98DX9、PAL98UNHAPPY 的速度、计时和读档规则，不改变进程匹配或进程内存读写地址。

配套版本：PalTimer 3.38.4（文件版本 3.38.4.1）/ Online 1.0.0.13，需同套原生 Auth 与公开登记及新的构建批准。此前 3.38.3.7 为 r55，3.38.4.0 / Online 1.0.0.12 为 r56/r57；冻结旧包保持原字节。服务端对应 othercat/PalServer#31，引擎对应 othercat/sdlpal-lostedit#139，八配置初始化对应 #38 与 othercat/sdlpal-lostedit#138。

本次补齐 `GForm.CreateCompetitionSnapshot` → `OnlineModule.ReadSnapshot` 的 `sdlpal.speed` / `sdlpal.battle_speed` 可选扩展。两端保留实际 0–100 的观测值；缺失不伪造为零，存在但格式错误或越界则拒绝；传统 PAL98 系列忽略 SDL 专属扩展。API 1 DTO 和配置摘要不变。原始与最终观测通过此桥后才进入普通通关签封路径；单独成功的初始化上传不能替代该路径验证。

## 历史实现记录（已由上述规则替代）

# 隔世追凶正常加减速

仅 `SdlpalGeshi` 允许运行中改变 `speed`、`battleSpeed`、`walkFrameMs`、`fadeCycleMs`，不再因此产生“计时期间资源、引擎或速度配置变化”。资源 profile、四项资源哈希、引擎 EXE 哈希和 build 仍参与完整性检查，观察到变化后不会因恢复原值而自动清除异常。

现行服务端 `timer_online_review.py` 比较开局和结束的完整 `gameplay`、`ranking.configuration_id` 及 `ranking.rules`，不同即记录 `changed_gameplay` / `changed_configuration`。为兼容既有 12 键契约，本轮榜单事实和本地最佳线使用首次开始计时时的四个速度值；资源和引擎仍取当前观察。重置后重新绑定起始速度。暂停、重连或调速不重新绑定分类，不清除已记录的读档、事件缺口及人工辅助标记。

这是起始配置分类，不表示全程速度未变。实际即时速度始终保留在游戏快照、`CurrentSnapshot` 及导出的 `SdlpalProfileData`；快照过期、格式错误、诊断模式及缺少有效时序仍会判无效。游戏自己按即时速度计算的配置尾号可能和本轮计时器分类不同，不能将其解释为服务器确认的分类或回执。

PB 文件命名及旧文件不变，本轮加减速不会换掉已加载的参考值和昵称，物品检测也保留已观察到的净变化。重置时起始速度不同仍选另一分类，不自动迁移或覆盖旧最佳线。时间线和 v1 接力包保留原身份字段格式，允许四个合法速度字段不同；仍核对资源、引擎、路线、存档摘要、进程创建时间和 epoch。接力成功后仍暂停且属于辅助跑次。

不修改 PAL98、PAL98DX9、PAL98UNHAPPY 的速度检查，也不改共享 CompetitionClient 的变更锁存或服务端审核。没有更改进程匹配、内存地址、读写进程内存、认证、版本号或冻结发布件。
