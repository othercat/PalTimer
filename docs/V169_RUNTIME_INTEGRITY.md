## 行为与边界

- `PAL98.RuntimeIntegrity.v1` 使用独立的 320 字节只读映射 `Local\PAL98.RuntimeIntegrity.v1.<pid>`。校验魔数、大小、版本、PID、内核创建时间、seqlock、QPC 频率和 3 秒内心跳。无样本不是作弊结论。初次连接给予诊断接口 30 秒就绪时间；已就绪后丢失有效心跳，或超过初始宽限期仍无有效诊断，提示“运行诊断不可用”。
- 计时器标题、版本显示、旧 OBS 数据、DX9 OBS 追加诊断；DX9 OBS 独立换行显示，不混入暂停状态。身法/吉运改写、随机数待核验、采样不完整等告警保留到目标游戏进程结束。计时器 Reset 或读档不清除同一 PID、创建时间、EXE 路径的记录；切换计时核心也从同进程记录恢复。
- 连接另一目标时，三个 98 内核立即清除旧目标显示，内部记录新目标尚未核验；标题与 OBS 不展示扫描进度。后台结果绑定目标代次，旧任务不能覆盖新目标；正常断开则保留最后目标的成绩证据。发布给 UI 的证据使用独立快照，后台不再修改已发布对象。
- 新诊断仅写显示和 `RuntimeIntegrity` 成绩元数据。不新增停止、强退、导出拒绝或上传拒绝。既有时序、硬核及云服务规则仍独立执行。
- 标题与 OBS 不显示“核验未完成”“文件匹配”“运行诊断不可用”、云认证标签、正常关闭/尚未覆盖/准备中的保护状态。“[测试版]”仅根据 PAL.dll 白名单生成，其它文件差异只记录，不决定该标签。原检测、历史异常保留及成绩中的 FileState/Mismatch、FileMismatchSeen 不变；实际读取失败及确认的运行告警保留。DiagnosticUnavailable 在游戏仍连接时照实记录，但任何时候都不生成标题标签；云 ID 和各项保护/核验状态仍完整写入成绩，原有云 ID 显示不变。这不宣称共享内存是不可伪造证明。

## 内嵌定版清单

源文件为 `Pal98Timer/release_integrity.v1.json`，嵌入名为 `Pal98Timer.release_integrity.v1.json`。加载器没有磁盘 JSON 覆盖入口。`frozen: false` 永远不能产生“文件匹配”。冻结需要以下内容：

| 字段 | 含义 |
|---|---|
| `schema` | 固定 `PAL98.ReleaseIntegrity.v1` |
| `release_id` | 冻结发布身份，可包含构建短哈希 |
| `build` | 与 native 诊断的 build 字段相同（当前为 `PAL_BUILD_VERSION_STRING`） |
| `files` | 所有内容共用核心文件，元素为 `path,size,sha256,module?,normalization?,enabled_by?` |
| `profiles` | `content_id,content_version,content_sha256,files,settings?`，按实际 TimingMode.v2 选择 |
| `graphics_chains` | `id,files,absent_files?`，必须匹配完整的一种组合 |
| `settings` | 规范化玩法设置：`file,section,key,value或allowed_values或min/max,default_value?,ignore_case?` |
| `memory_regions` | `id,module,rva或pointer_rva,expected,fixups?,protection_states?` |
| `exact_directories` | 可选；仅 `copymen_scripts` 的单层可执行脚本文件名集合 |

所有文件路径均相对于目标 PAL 目录，使用 `/`；拒绝绝对路径、越界、链接路径、重复文件条目。`module` 指定该文件必须来自预期目录的实际加载模块。

r10 模块 `normalization=copymen-enabled-v1` 只把顶层 enabled 的布尔值规范化为 false，UTF-8 BOM 视为编码传输标记，其余文本保持原字节身份；重复 enabled、非法 JSON 或超过 64 KiB 均拒绝。`enabled_by` 引用清单中明确的模块路径：先核验模块，再决定是否检查载荷；不会忽略模块或把开启后的资源跳过。构建冻结时所有载荷仍须存在且匹配。

r10 设置可改用成对的整数 min/max，和 value/allowed_values 互斥；范围及缺省都严格校验。只有登记了 ignore_case 的文本枚举按忽略大小写比较（例如运行库本来忽略大小写的 DefaultPatch/技能池选项）。未知内容不产生官方匹配结果，但仍核验公共核心、脚本与当前图形链，不提前返回而留下检查缺口。

`settings` 的节/键大小写不敏感，去除首尾空白，十进制整数规范化；`true`/`false` 忽略大小写后规范化为 `1`/`0`。`value`、`allowed_values`、成对 `min/max` 严格三选一；允许列表含 1 至 64 个值，不接受规范化后重复的值（包括 `true` 与 `1`）。缺失键只有显式声明 `default_value` 才采用默认值，该默认值仍须满足同一允许集合或范围；空值不冒充缺失。重复键不猜测优先级。仅冻结玩法字段，合法按键、音乐、语言、窗口位置等不应进入清单。设置不匹配只产生“玩法设置与登记配置不符”，标题、OBS 和普通成绩摘要不显示内部参数名。

INI 行内注释遵循 ConfigTool 的引号与空白边界：引号外、前面有空白的 `;` 或 `#` 开始注释；引号内或字符串路径中紧连的分号/井号保留。数字型清单值另允许完整整数或布尔词后紧跟 `;`/`#`，对应 native 数值读取及 `wtime_config_policy.h` 的合法注释行为。不会将 `10x;...`、小数或路径前缀猜成整数。已验证真实 Win32 整数读取能接受 `10;说明`。

`memory_regions.expected` 为完整十六进制字节。重定位和已核实 Hook 的 `fixups` 必须明确 `offset,module,rva,kind`；kind 仅 `abs32`、`rel32`。运行时按实际模块基址计算预期值，不把启动内存作为基线，不接受任意通配掩码。可选 `protection_states` 为允许核验的保护状态数值数组；只有按开关安装的角色 dispatch 使用该限制，普通/RNG 入口仍始终核验。首个稳定诊断心跳表示 native 初始化已发布，Preparing 表示等待合法角色基线，并不暂停 RNG 代码核验。同一已连接目标后续丢失心跳时，普通/RNG 代码继续独立轮验；需要保护状态的条件区域保持未完成，直至重新获得状态。

固定代码使用 `rva`；Detours 堆内跳板使用 `pointer_rva`，两者必须且只能给一个。`pointer_rva` 是指定已加载模块内的固定 4 字节指针槽，读取其 `uint32` 值作为实际区域地址，`rel32` 以该实际区域地址计算。检查槽边界、目标 32 位地址范围、完整预期长度及重定位偏移；核验后重读槽，变化时显示未完成。地址不由共享诊断提供，指针为空/不可读与字节不匹配分别处理。具体指针槽和原字节仍必须由匹配 native 构建给出，合成宿主测试不代表真实 PAL 跳板已验收。

WOW64 下的 Toolhelp `MODULE | MODULE32` 可以重复返回同一路径/基址/大小的主程序，并同时返回两种位数的系统 `ntdll.dll`。ReShade 的游戏目录 `d3d9.dll` 也会与 Windows 的同名 DLL 共存。完全一致的条目合并，其余物理实例全部保留。清单文件有明确的预期完整路径时，只匹配该路径的唯一模块身份；期望路径不存在仍报告不匹配，同一路径有不同基址或大小则显示未完成。代码源和 fixup 按名称引用仍要求唯一身份，不从多个候选中任选。未被引用的系统模块不阻断核心代码核验。

`exact_directories` 最多一项，`path` 必须为 `copymen_scripts`，`extensions` 必须恰含 `.json`、`.txt`、`.rule`。`entries` 为至多 256 个安全单层文件名，忽略大小写后不可重复。核验只枚举这一层，不进入子目录、不扫描 Tools/音乐/存档；实际缺少/多出脚本或目录不存在为不匹配。目录/条目为重解析点、访问失败或条目超过单轮上限为未完成。该集合检查配合已登记文件的 SHA-256，补上“额外加入一个未登记脚本”的缺口。字段缺省时兼容旧测试清单；正式清单应填写。

轻量运行观察每 500 ms 最多调度一次，跨计时核心共用互斥扫描门。首次文件核验每片最多 512 KiB；完整一轮结束至少 5 分钟后才再扫，后续复核每秒最多一片、每片最多 256 KiB。一次片段最多完成一个文件，大文件分片续读；每次读取之间用 QPC 检查约 2 ms 软预算。模块清单每 10 秒更新，关键代码每次观察轮转一项。

脚本目录与设置逐项使用该片剩余预算，保存游标后续继续。每轮同一 INI 只读一次，文件上限 1 MiB、总缓存上限 4 MiB，完成时再次检查长度和修改时间。磁盘系统调用或 JIT 本身可能超过软预算，工作始终在后台执行。节点回调没有文件读取、哈希、等待或新检测任务；不修改节点条件、计时来源及暂停行为，不追赶过期扫描。后台工作仍使用少量系统资源，不能据自动测试宣称所有旧硬件都无资源竞争。

相同目标及内容的正常复核期间保留上次完成结果，另记录 `FileRecheckInProgress` 与 `FilesVerifiedAtQpc`；真实读取失败立即标记并显示“核验读取失败”，不以旧成功掩盖错误。工作阶段快照仅用于内部保留告警，最终才发布到 UI。seqlock 最多重试三次，仅写入碰撞时允许沿用同一进程原心跳尚未过期的快照；失效/缺失映射不沿用，时间戳在复制后获取，避免把新心跳误认作未来时间。
