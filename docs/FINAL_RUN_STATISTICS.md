# 通关整体成绩统计

Refs othercat/PalTimer#63、othercat/sdlpal-lostedit#289、othercat/PALDLL_DX9#290、othercat/PalServer#71。

统一计时器的原版与 SDL 内核发布 `observations.final_statistics` (`PAL.RunStatistics.v1`)：通关最终金钱、每位实际可操作物理角色的确认倒地次数和战败次数。该字段和整场成绩一起签封、保存 Outbox 和重试，不改变计时、榜单、挑战身份或原有资格规则。

SDL 读取引擎桥的进程累计事件；原版读取严格识别 PAL.EXE 字节后启用的 `Local\PAL98.RunStatistics.v1.<pid>` 只读协议。原版协议验证 PID、进程创建时间、版本、能力和 seqlock；金钱另行成功读取实时 DWORD。SDL 读取 cashBalance，保留改版负债的负值。原版 DLL 不联网。

死亡按行动/回合确认边界的正 HP 到倒地变化计数，不把红屏、瞬间临时写零或低频读取 HP 当作死亡次数。复活后可以再次死亡；重复死亡帧不重复。统计按角色 ID，SDL 包含0–5的六个角色，原版支持当前原生可控队伍和至多16角色属性表。r7不构建的实验虚拟队伍不因此启用。

普通游戏读档不清累计。重置跑次建立新的差分起点。时间线/云接力保存 `RunStatisticsState` 和累计游标；导入会衔接保存游标至当前快照间可确认的事件，并保持已有尝试的最大累计、标记不完整。恢复世系避免新进程事件被重复导入；同一来源游标只前进，迟到旧快照不会令死亡/战败重新累计。捕获与重置/恢复共用顺序，不把倒退读档当作复活。进程更换保留本跑累计，但无法证明旧进程末尾连续性，因此 complete=false。

保留原有最终节点的停表点、总时间和通关时间戳。原版的 Boss 血量归零可能早于金钱结算，因此统计等当前战斗结算后再冻结并签封；SDL也不把战果发布但奖励未完成时的钱数当作最终值。一次读失败不会提前结束结算等待，恢复后的有效累计与余额仍可收敛。确认进程退出、来源原本缺失或连续读取失败超过5秒，最终金钱为 null 并标记不完整，成绩仍可保留。冻结后的事件、金钱或网络重试不修改原成绩。来源缺失时战败为 null、角色列表为空；complete=false 用于分析区分观察缺口，不拒绝原有可提交的成绩。

生产发布顺序：先部署 PalServer #71 的接收合同，再批准新 EXE/Online/Auth 的准确组合。客户端等待 `final-run-statistics.v1` 能力；旧服务不支持时原样保留整个成绩和签封，低频等待升级，不剥离统计或重签旧成绩。忽爷云的核心名与新 EXE MD5 是另一套既有运维登记，不能沿用旧哈希；客户端不会自动批准或变更后台身份。旧 DLL/计时器组合只声明缺统计，不假造0。回退应成套恢复旧 EXE、Online、Auth 与公开组合登记。

本轮验证只执行合成计数、只读共享内存夹具、真实宿主到 API1 扩展到 Online 到最终 JSON 的离线链路和服务器测试。没有运行游戏或发出游玩输入。

关闭计时器前会把已通关但尚待结算的成绩先交给既有Outbox排队；未能取得的最终钱数标未知，不丢失整体完成记录。未通关时关闭不会伪造通关成绩。
