# 隔世 r26：读档、死亡和重开后的自动续计

对应 [PalTimer #31](https://github.com/othercat/PalTimer/issues/31)，2026-10-18。

## 原因

r23/r24 的重连修复只允许替换进程后自动续计。同一进程中的普通读档仍调用 `PauseForLoad()`，将 `IsUIPause` 置为 true，和用户按 F8/F9 无法区分。这种自动生成的暂停还会被下一次进程重连保留，因此出现“读档后停表，关闭再进仍停表”。

简单版死亡脚本在红屏、对白结束后执行 `004E`，同进程加载当前存档；快照的 `epoch` 增加，但 `started` 一直为 true，因而同样触发旧分支。原始 SSS SHA256：`92efd5ec75dc945f3620f96f61e38879fdc0c605f5916d1143c36a4311ad57f4`，死亡序列从 `9C9B` 到 `9CA2`。

隔世核心及游戏生命周期没有以香蕉物件 `0x123` 决定开始或暂停计时。传统 PAL98 核心有自己的香蕉树反作弊逻辑，本次不改它。

## 行为

只修改 `SdlpalGeshi.OnTick` 的普通加载暂停分支，并移除不再需要的重连特例状态。有效前台游戏自动继续；失焦、标题、进程退出、快照失效时停表。普通/快速/死亡读档不生成手动暂停。F8/F9 主动暂停、接力/云档/时间线导入暂停仍保留；已通关不会重新走表。

累计时间和已完成节点保留，读档时旧战斗副表清零；成绩审核仍记录读档/重启，不把辅助跑次改成完整新跑次。没有改游戏资源、存档、内存读写地址、进程匹配或联机协议。PAL98、DX9、UNHAPPY 内核无需同步。

## 验证

- 新回归在修复前失败：无香蕉、普通读档、未主动暂停，实际被写入手动暂停。证据 `artifacts/sdlpal-tests-20261018-222613-535/result.txt`。
- VS2026 Release x64 构建通过；修复后现有隔离 MMF / 真实宿主行为套件共 587 项通过。证据 `artifacts/sdlpal-tests-20261018-222640-707/result.txt`。
- 新增 24 组：有/无香蕉 × 普通读档/死亡读档/读档后重开 × 未暂停/F8/F9/接力暂停；同时断言焦点恢复、累计时间、已完成节点、手动暂停次数与独立的实时/成绩状态。保留既有跨 PID/创建时间重连、战斗副表、通关、时间线、热键等回归。
- 无用户游戏进程、全局按键钩子或生产网络会话；MMF 使用独立随机名字，不被正在运行的玩家工具发现。死亡脚本链为真实资源的只读核对，未把合成快照测试写成玩家原存档实跑。

玩家复测：退出旧计时器后更新四件套；未手动暂停时，正常读档、死亡后自动读档、关闭游戏再进入应续计。按 F8/F9 暂停后重复上述操作应保持暂停，再按一次继续。新构建的服务端批准仍独立处理。

回退：退出计时器，恢复原 EXE/Online/Auth/公开登记四件套；个人设置不需要回退。修改前源码备份在 `artifacts/r26-timer-resume-before`。未暂存、提交或推送。
