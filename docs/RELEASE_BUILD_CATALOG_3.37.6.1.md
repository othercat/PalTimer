# 子版本核验清单（计时器 3.37.6.1）

## 3.37.6.2 更新

新增 PALDLL 1.6.8.12 的内嵌核验基线，保留 1.6.8.11 基线；支持新诊断生产者版本和对应锁版本元组。计时器仍显示 3.37.6，内部版本和文件哈希递增。正式 DLL 名单未扩充，计时/暂停/节点与云协议未改动。新 EXE 需按最终 SHA-256 重新登记云激活。

计时器自身显示 3.37.6，内部版本和成绩记录为 3.37.6.1；PAL 游戏仍显示 1.68。DLL 生产者版本、成绩、诊断、发布清单保留完整子版本与 SHA-256。

## 两份名单职责不同

- 支持核验的构建目录：保留原内嵌清单，新增 `release_integrity.1.6.8.11.v1.json`。按目标进程实际 PAL.dll 大小/SHA-256 选择清单及相应代码预期值。
- 用户指定正式 DLL：仍只有原先指定的 1.6.8.10、1.14、1.02 三份哈希。本轮 1.6.8.11 候选不加入正式名单，正确匹配构建清单也显示“测试版”。版本字符串不代替哈希。

未知 DLL 不套用其它子版本的进程代码基线，不因版本不同直接声称内存篡改。已识别构建仍独立核验文件和关键运行代码；成功不增加标题文字。新增诊断不阻断节点计时或启动。

## 冻结顺序

`tests/freeze_release_catalog.py` 读取同次构建 DLL/MAP，核对 PE 时间戳和映像基址，生成随机数/数值保护区段预期值及重定位规则。只有 DLL、Helper 和明确允许的设置被更新；其它核心文件必须仍匹配经过审阅的基准。发布包新增内容 Profile 需逐资源核对外部清单和实际 ZIP。

清单记录完整构建号、源码 HEAD 以及工作区源码清单 SHA-256；随后编译计时器，记录最终计时器 EXE 哈希供重新登记云激活。修改外部 JSON 不能改变编译内嵌预期值。

后台仍采用首轮 512 KiB、后续 256 KiB 的分片预算，每片最多完成一个文件，轮次间隔五分钟；节点计时路径不执行整包哈希、不等待扫描。锁定标题资源由 DLL 的签名和独立失效回退处理，不纳入玩法硬依赖失败。

## 验证

定向测试 24 个场景、745 条断言；包括不同构建选择、未知 DLL、不增加成功标签、未覆盖内容仍检查公共核心、合法模块开关、分片预算和正式名单不被候选扩充。独立运行副本另用计时器真实读取器核验 19 个代码区段及文件清单，结果见部署证据。云激活和跨主机结果不由离线测试代替。
