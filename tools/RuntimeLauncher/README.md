# 自动选择计时核心

Refs othercat/sdlpal-lostedit#223。

将 `PalTimerAuto.exe` 与原版及 SDL 共用的 `Pal98Timer.exe` 放在同一目录。
它在启动时选择原版 `Pal98Dx9Automatic` 或 SDL `SdlpalGeshi`，然后退出。
前台游戏优先；只有一种运行时在运行时选该运行时；两种同时运行且焦点不在游戏时，
使用本安装目录的正在运行游戏。没有游戏进程时使用所在完整包的游戏程序。
无法判定时提示玩家先切到目标游戏窗口。支持维护游戏 EXE 改名。

识别基于游戏程序内容，不根据进程名、窗口标题或 `LastCore` 猜测。
SDL 要求 PE、SDL2 及 LostEdit 桥标记；原版要求已核实的原 PAL98 程序摘要。
新原版 EXE 身份需要先增加证据，未知程序不会套用固定内存核心。
只查询进程路径并读取磁盘 EXE，不读写进程内存、不注入、不调用游戏动作。

自动选核只在打开计时器时发生。已有计时器会保留计时并提示关闭；切换游戏后，
关闭计时器再用此入口打开。直接打开 `Pal98Timer.exe` 仍使用手动选择及上次核心。
显式 `--core <名称>` 优先于自动识别；其他参数原样传给原计时器。
`--probe` 只输出选择和参数，不启动程序、不改设置、不请求网络。

计时器、Online、Auth 和公开登记均复用同一次正式构建的原字节；启动器不代替认证，
不改变计时/暂停/云档/榜单/规则优先级，也不在运行中自动切换核心或重置当前跑次。
构建与测试入口为 `build.ps1`，全部输出必须指定到实际 Issue artifacts 子目录。
